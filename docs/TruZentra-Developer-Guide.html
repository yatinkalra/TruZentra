4. Adding an Apex Service

Step 1: Create the Service Class

public without sharing class ZentraNewFeatureService {

    public class FeatureRequest {
        @InvocableVariable(label='Customer Id' required=true)
        public Id customerId;
        // Add more inputs
    }

    public class FeatureResponse {
        @InvocableVariable(label='Success')
        public Boolean success;
        @InvocableVariable(label='Message')
        public String message;
        // Add more outputs
    }

    @InvocableMethod(label='Your Feature Label'
        description='Description for the agent'
        category='Your Category')
    public static List<FeatureResponse> execute(
            List<FeatureRequest> requests) {
        List<FeatureResponse> results = new List<FeatureResponse>();
        for (FeatureRequest req : requests) {
            FeatureResponse resp = new FeatureResponse();
            try {
                // Your logic here
                resp.success = true;
                resp.message = 'Done.';
            } catch (Exception e) {
                ZentraErrorLogger.log(
                    'ZentraNewFeatureService', 'execute',
                    e, req.customerId);
                resp.success = false;
                resp.message = 'Error: ' + e.getMessage();
            }
            results.add(resp);
        }
        return results;
    }
}

Step 2: Create the Test Class

@IsTest
private class ZentraNewFeatureServiceTest {
    @TestSetup
    static void setup() {
        Account acct = new Account(Name = 'Test Customer');
        insert acct;
        // Create related test data
    }

    @IsTest
    static void testHappyPath() {

        ZentraNewFeatureService.FeatureRequest req =
            new ZentraNewFeatureService.FeatureRequest();
        req.customerId = acct.Id;

        Test.startTest();

            ZentraNewFeatureService.execute(
                new List<ZentraNewFeatureService.FeatureRequest>{req});
        Test.stopTest();

    }
}

Step 3: Create the meta XML

<?xml version="1.0" encoding="UTF-8"?>

    <apiVersion>65.0</apiVersion>
    <status>Active</status>

Rule: Every service MUST wrap logic in try-catch and log errors via ZentraErrorLogger.log(). Every service MUST have a corresponding test class.

5. Adding a Flow

Flows are the bridge between the Agent and Apex. Every agent action maps to a Flow which calls an Apex Invocable.

Pattern

  1. Create an Autolaunched Flow named Zentra_Your_Action
  2. Add input variables matching the action schema (varCustomerId, etc.)
  3. Add an Apex Action element calling your Invocable
  4. Map outputs to Flow output variables
  5. Set Flow to SystemModeWithoutSharing if the agent user lacks object access
FSC DML: If your service updates FinServ__FinancialAccount__c or other FSC objects, use ZentraSystemDMLHelper to avoid PSL validation errors.

6. Adding an Agent Topic

Step 1: Add Topic to Planner Bundle

Add a <localTopics> entry in TruZentra.genAiPlannerBundle with:

  • fullName / developerName
  • description — what the topic does (this helps the planner route)
  • genAiPluginInstructions — ordered instructions for the agent

Step 2: Add Action Schemas

Create directories under localActions/{topicFullName}/{actionFullName}/:

localActions/
  YourTopic_16jbm000001M6z3/
    YourAction_179bm000002PuxX/
      input/
        schema.json      # Input parameters
      output/
        schema.json      # Output parameters

Example schema.json (input)

{
  "properties": {
    "input_varCustomerId": {
      "type": "lightning__textType",
      "title": "Customer Id",
      "copilotActionProperties": {
        "isUserInput": false,
        "isDisplayable": false,
        "isUsedByPlanner": true
      }
    }
  }
}

Step 3: Add Attribute Mapping

Add an <attributeMappings> entry to wire VerifiedCustomerId to the action input:

<attributeMappings>
    <attributeName>YourTopic.YourAction.input_varCustomerId</attributeName>
    <attributeType>CustomPluginFunctionAttribute</attributeType>
    <mappingTargetName>VerifiedCustomerId</mappingTargetName>
    <mappingType>Variable</mappingType>
</attributeMappings>
Critical: Without input/schema.json and output/schema.json, the agent will silently skip the action. No error, no log — just silent failure.

Step 4: Add Instructions

Every topic MUST include these instruction patterns:

  • Auth gate: "Customer MUST be OTP-verified. If VerifiedCustomerId is not available, redirect to OTP."
  • Language match: "ALWAYS reply in the same language the customer uses."
  • Post-task menu: After completing, show the 8-option menu.

10. Deployment

Follow these steps in order for a clean first-time deployment to a fresh org. Every step is required.

10.1 Prerequisites

  • Salesforce CLI (sf) installed and authenticated to the target org
  • Target org must have Financial Services Cloud and Agentforce enabled
  • Target org must have Data Cloud provisioned (for Calculated Insights & 360 Dashboard)
# Authenticate
sf org login web --alias TruZentra --instance-url https://[your-instance].salesforce.com

sf apex run --file scripts/setup-customer.apex --target-org TruZentra

10.4 Step 3 — Create the TruZentra Agent

The Agent (Bot) definition cannot be deployed across orgs via metadata due to org-specific dependencies (botUser, entryDialog). Create it manually:

  1. Go to Setup → Agents → New Agent
  2. Template: Agentforce Service Agent
  3. Label: TruZentra  |  API Name: TruZentra
  4. Save the agent (do not activate yet)

10.5 Step 4 — Create Agent Variables

In Agent Builder → TruZentra → Variables, create these three variables:

Variable NameTypePurpose
isVerifiedBooleanSet to true after OTP/MPIN verification
VerifiedCustomerIdTextStores the Account Id of the verified customer
authenticationKeyTextHolds the OTP session Id between Send OTP → Verify OTP

10.6 Step 5 — Deploy the Agent Bundle

Now that the agent and variables exist, deploy the bundle:

sf project deploy start \
  --source-dir force-app/main/default/genAiPlannerBundles \
  --target-org TruZentra --wait 10
Agent must be deactivated first! If redeploying changes to TruZentra.genAiPlannerBundle, you must deactivate the TruZentra agent in Setup → Agents before deploying. Reactivate after deploy.

Each topic below is deployed automatically with the bundle. The table shows what each topic does, its scope (trigger phrases), key instructions, and linked actions/flows.

Topic 1 — OTP Verification

FieldValue
Developer NameZentraOTPVerification
DescriptionVerifies customer identity using OTP (sent to registered EMAIL only, never SMS) or MPIN. This MUST happen FIRST in every conversation.
ScopeFirst topic in every conversation. Greet warmly, ask for mobile number, offer OTP (email) or MPIN. If Account Not Found, pitch new account. After verification, greet by name and show menu. Never repeat verification in same session. Reply in customer’s language.
GuardrailNone (this is the authentication topic itself)

Instructions:

  1. auto_send_otp_on_first_message — On first message, greet warmly, ask for mobile. Offer: (1) OTP via email, (2) MPIN. If OTP → call SendOTP. If Account Not Found → pitch new account. If MPIN → ask for 6-digit PIN, call VerifyMPIN.
  2. send_otp_instruction — Pass phone number. OTP goes to EMAIL only (never SMS). Check “Account Not Found” output.
  3. prompt_for_otp_code — Tell customer to check email for 6-digit code. Never mention SMS. Never reveal OTP.
  4. verify_otp_instruction — Pass OTP code + session Id from SendOTP.
  5. handle_failed_otp — Empathetic retry message. After max attempts, session locked 30 min.
  6. otp_expiry_handling — OTP valid 5 min. If expired, re-send with SendOTP.
  7. authentication_required — Never process sensitive requests without OTP.
  8. prevent_reverification — Once verified, never re-verify in same session. No switching customers.
  9. proceed_after_success — Greet by name (“Thank you, [Name] ji!”), show 8-item menu. If customer already asked for something, handle immediately.
  10. security_confidentiality — Never reveal OTP code, session Id, or tokens.
  11. handle_account_not_found — If no account, pitch new account warmly. If YES → collect name+email, call RequestNewAccount. If NO → farewell.
  12. mpin_verification_option — MPIN is 6 digits like OTP. If ambiguous, ask “Is that your MPIN or OTP?” If MPIN not set, auto-fallback to OTP.

6d. Create Churn Risk Calculated Insight

Go to Data Cloud → Calculated Insights → New. Name: Zentra_Customer_Churn_Risk. Schedule: Daily. Paste the SQL below:

SELECT
  ind.ssot__Id__c                                  AS IndividualId__c,
  ind.ssot__FirstName__c                           AS FirstName__c,
  ind.ssot__LastName__c                             AS LastName__c,
  COALESCE(fa_stats.total_accounts__c, 0)          AS total_accounts__c,
  COALESCE(fa_stats.inactive_accounts__c, 0)       AS inactive_accounts__c,
  COALESCE(rp_stats.active_rp__c, 0)               AS active_rp__c,
  COALESCE(rp_stats.stopped_rp__c, 0)              AS stopped_rp__c,
  COALESCE(disp_stats.open_disputes__c, 0)         AS open_disputes__c,
  COALESCE(txn_stats.txn_count__c, 0)              AS txn_count__c,
  CASE
    WHEN COALESCE(fa_stats.total_accounts__c, 0) = 0 THEN 80
    ELSE 0
  END
  + CASE
      WHEN COALESCE(fa_stats.inactive_accounts__c, 0) > 0 THEN 30
      ELSE 0
    END
  + CASE
      WHEN COALESCE(rp_stats.stopped_rp__c, 0) >
           COALESCE(rp_stats.active_rp__c, 0) THEN 25
      ELSE 0
    END
  + CASE
      WHEN COALESCE(disp_stats.open_disputes__c, 0) > 0 THEN 20
      ELSE 0
    END
  + CASE
      WHEN COALESCE(txn_stats.txn_count__c, 0) = 0 THEN 15
      WHEN COALESCE(txn_stats.txn_count__c, 0) < 5 THEN 5
      ELSE 0
    END                                             AS churn_score__c
FROM ssot__Individual__dlm ind
LEFT JOIN (
  SELECT ssot__PrimaryAccountId__c                  AS acct_id__c,
         COUNT(*)                                   AS total_accounts__c,
         SUM(CASE WHEN ssot__Status__c = 'Inactive' THEN 1 ELSE 0 END)
                                                    AS inactive_accounts__c
  FROM   ssot__FinancialAccount__dlm
  GROUP BY ssot__PrimaryAccountId__c
) fa_stats ON fa_stats.acct_id__c = ind.ssot__Id__c
LEFT JOIN (
  SELECT Zentra_CustomerId__c                       AS cust_id__c,
         SUM(CASE WHEN Zentra_Status__c = 'Active' THEN 1 ELSE 0 END)
                                                    AS active_rp__c,
         SUM(CASE WHEN Zentra_Status__c = 'Cancelled' THEN 1 ELSE 0 END)
                                                    AS stopped_rp__c
  FROM   Zentra_Recurring_Payment__dlm
  GROUP BY Zentra_CustomerId__c
) rp_stats ON rp_stats.cust_id__c = ind.ssot__Id__c
LEFT JOIN (
  SELECT Zentra_CustomerId__c                       AS cust_id__c,
         SUM(CASE WHEN Zentra_Status__c IN ('New','Under Investigation') THEN 1 ELSE 0 END)
                                                    AS open_disputes__c
  FROM   Zentra_Dispute_Case__dlm
  GROUP BY Zentra_CustomerId__c
) disp_stats ON disp_stats.cust_id__c = ind.ssot__Id__c
LEFT JOIN (
  SELECT ssot__AccountId__c                         AS acct_id__c,
         COUNT(*)                                   AS txn_count__c
  FROM   ssot__FinancialAccountTransaction__dlm
  GROUP BY ssot__AccountId__c
) txn_stats ON txn_stats.acct_id__c = ind.ssot__Id__c

Scoring logic: No accounts = +80, inactive account = +30, more stopped than active recurring = +25, open disputes = +20, zero txns = +15, <5 txns = +5. Score 0–100.

CI SQL constraints.
  • No table aliases (use subqueries with column aliases instead)
  • No COUNT(DISTINCT) — use SUM(CASE WHEN ... THEN 1 ELSE 0 END)
  • No CAST, LEAST, NULLIF
  • All output column aliases must end with __c
  • Always query DMOs (__dlm), never DLOs (__dll)
  • LIKE on __dll objects is case-sensitive — always fetch broadly and filter in Apex with toLowerCase().contains()

12. Common Gotchas

One @InvocableMethod per class. Salesforce enforces this. If you need a second invocable, create a new class.
FSC PSL Validation. The agent user may lack FSC Permission Set License. Use ZentraSystemDMLHelper for any DML on FinServ__ objects.
DML before callout. You cannot perform DML (including error logging) before an HTTP callout in the same transaction. Log errors AFTER callouts.
Data Cloud LIKE is case-sensitive. On __dll objects, always fetch broadly and filter in Apex with toLowerCase().contains().
Guest user file upload. Standard forceContent:fileUpload fails silently for guest users. Use the custom zentraFileUpload LWC with ZentraFileUploadController.
Session ID in Flow context. UserInfo.getSessionId() is invalid for REST callouts from Flow. Use ZentraSessionHelper.page VF page to get a valid session.
CI SQL constraints. No aliases, no COUNT(DISTINCT), no CAST/LEAST/NULLIF. All output aliases must end with __c. Use DMOs (__dlm) not DLOs (__dll).
